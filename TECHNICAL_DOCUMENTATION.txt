================================================================================
                         1. SYSTEM OVERVIEW
================================================================================

The Railway Wagon Inspection System is an end-to-end AI video processing 
pipeline designed for:
- Railway wagon counting
- Damage detection
- OCR-based wagon identification logging
- Real-time visual feedback and monitoring

TARGET ENVIRONMENT:
- Windows 11 machine
- NVIDIA RTX 3050 GPU (6 GB VRAM)
- Real-time or near-real-time inference
- Fast-moving vehicles (50-80 km/h)
- Day and night-time footage support

KEY FEATURES:
- YOLOv11n-based wagon and damage detection
- ByteTrack multi-object tracking
- MPRNet ROI-only deblurring (FP16 with FP32 fallback)
- EasyOCR text extraction with visual feedback
- CLAHE enhancement for low-light conditions
- OCR bounding box visualization with confidence overlays
- Processing status indicators (Illumination, Deblur, OCR)
- Configurable OCR frame interval control
- Automatic frame saving with JSON metadata
- CSV/JSON logging with debug frame output
- Streamlit-based Mission Control Dashboard


================================================================================
                           2. ARCHITECTURE
================================================================================

The system follows a multi-stage pipeline architecture:

PROCESSING STAGES:
------------------
Stage 1:  Frame Capture        - Video source to OpenCV frame capture
Stage 2:  CLAHE Enhancement    - L-channel only enhancement for detection
Stage 3:  Wagon Detection      - YOLOv11n detects wagons (RAW/CLAHE only)
Stage 4:  ROI Extraction       - Extract text region ROI (NOT full wagon)
Stage 5:  ROI Resizing         - Resize to max 256px width (aspect preserved)
Stage 6:  Blur Gating          - Compute Laplacian variance on resized ROI
Stage 7:  N-th Frame Check     - Determine if MPRNet should run this frame
Stage 8:  MPRNet Deblur        - FP16 inference on ROI (if needed)
Stage 9:  OCR                  - EasyOCR on raw or deblurred ROI
Stage 10: OCR Visualization    - Draw bounding boxes and text overlays
Stage 11: Damage Detection     - Parallel YOLOv11n on RAW wagon ROI
Stage 12: Tracking             - ByteTrack for wagon ID assignment/counting
Stage 13: Frame Saving         - Save OCR frames with JSON metadata
Stage 14: Logging              - CSV/JSON output with all metadata

KEY DESIGN CONSTRAINTS:
-----------------------
- YOLO models receive ONLY RAW or CLAHE-enhanced frames (never deblurred)
- MPRNet deblurring is applied ONLY to small, resized OCR ROIs
- Deblurring runs every N frames (N=3-5), reusing results for intermediate
- FP16 inference for memory efficiency with FP32 fallback
- OCR accuracy is prioritized over visual beauty
- GPU memory is carefully managed to stay within 6 GB VRAM
- NAFNet is NOT used anywhere in the pipeline

================================================================================
                    5. PROCESSING PIPELINE FLOW
================================================================================

FRAME PROCESSING SEQUENCE:
--------------------------

1. FRAME CAPTURE
   Input:  Video source (file or RTSP stream)
   Output: Raw BGR frame (np.ndarray)
   
2. CLAHE ENHANCEMENT (Optional)
   Input:  Raw BGR frame
   Output: Enhanced BGR frame (L-channel only modified)
   Note:   Used for detection, preserves color information
   
3. WAGON DETECTION
   Input:  RAW or CLAHE-enhanced frame (NEVER deblurred)
   Output: List[WagonDetection] with bboxes and confidence
   Model:  YOLOv11n (damage_detector.pt - contains wagon classes)
   
4. WAGON TRACKING
   Input:  List[WagonDetection], frame_shape
   Output: List[TrackedWagon] with IDs and crossing status
   Algorithm: ByteTrack
   
5. ROI EXTRACTION
   Input:  Frame, WagonDetection
   Output: Wagon ROI (np.ndarray)
   Note:   Clips to frame boundaries
   
6. ROI RESIZING
   Input:  Wagon ROI
   Output: Resized ROI (max 256px width), scale_factor
   Note:   Maintains aspect ratio, no upscaling
   
7. BLUR DETECTION
   Input:  Resized ROI
   Output: blur_score (float), BlurDecision
   Method: Laplacian variance
   
8. OCR INTERVAL CHECK (NEW)
   Input:  frame_index, ocr_interval
   Output: should_run_ocr (bool)
   Logic:  Run OCR if frame_index % interval == 0
   
9. CONDITIONAL DEBLURRING (N-th Frame)
   Input:  Resized ROI, wagon_id, frame_index
   Output: Processed ROI (raw or deblurred), deblur_applied, source_frame
   Logic:
     - If blur_score >= threshold: return raw ROI
     - If frame_count % N == 0: run MPRNet, cache result
     - Else: return cached result
   
10. OCR EXTRACTION
    Input:  Processed ROI (raw or deblurred)
    Output: OCRResult with text and confidence
    Engine: EasyOCR with GPU acceleration
    
11. OCR VISUALIZATION (NEW)
    Input:  Frame, OCR detections, wagon bbox, deblur_applied
    Output: Annotated frame with OCR bounding boxes and text overlays
    Features:
      - Cyan bounding boxes around detected text
      - Text overlays with confidence percentages
      - Orange text for low confidence (< 50%)
      - Semi-transparent backgrounds for readability
    
12. DAMAGE DETECTION
    Input:  RAW wagon ROI (NEVER deblurred)
    Output: List[DamageDetection]
    Model:  YOLOv11n (wagon_detector.pt - contains damage classes)
    
13. OCR FRAME SAVING (NEW)
    Input:  Annotated frame, OCR detections, metadata
    Output: Saved JPEG frame + JSON metadata file
    Trigger: When OCR detects text
    
14. LOGGING
    Input:  All detection results
    Output: WagonRecord to CSV/JSON
    Note:   Includes deblur metadata

WAGON EXIT HANDLING:
--------------------
When a wagon exits tracking:
1. DeblurManager.clear_cache(wagon_id) is called
2. Cached deblurred ROI is freed
3. Frame counter for wagon is reset


================================================================================
                      6. GPU MEMORY MANAGEMENT
================================================================================

MEMORY CONSTRAINTS:
-------------------
- Target GPU: NVIDIA RTX 3050 (6 GB VRAM)
- Memory limit: 6 GB
- Warning threshold: 70% (4.2 GB)
- Critical threshold: 90% (5.4 GB)

MEMORY OPTIMIZATION STRATEGIES:
-------------------------------

1. ROI-ONLY DEBLURRING
   - MPRNet processes only small ROIs (max 256x256 pixels)
   - Full-frame deblurring is explicitly prohibited
   - Reduces memory footprint significantly

2. FP16 INFERENCE
   - MPRNet uses half-precision (FP16) by default
   - Reduces memory usage by ~50%
   - Automatic FP32 fallback on numerical instability

3. N-TH FRAME EXECUTION
   - MPRNet runs every N frames (default: 3)
   - Cached results reused for intermediate frames
   - Reduces GPU load while maintaining quality

4. OCR FRAME INTERVAL
   - OCR runs every N frames (default: 5)
   - Configurable via dashboard slider (1-30)
   - Reduces GPU load from EasyOCR

5. BATCH SIZE = 1
   - MPRNet always uses batch size 1
   - Prevents memory spikes from batching

6. CACHE MANAGEMENT
   - Deblurred ROIs cached per wagon
   - Cache cleared when wagon exits tracking
   - Prevents memory accumulation


================================================================================
                        7. ERROR HANDLING
================================================================================

EXCEPTION HIERARCHY:
--------------------
PipelineError (base)
├── ModelNotFoundError      - Model file missing
├── ModelLoadError          - Model loading failed
├── VideoSourceError        - Video cannot be opened
├── StreamConnectionError   - Stream connection failed
├── ConfigurationError      - Invalid configuration
├── FrameProcessingError    - Frame processing failed
├── GPUMemoryError          - GPU memory exhausted
├── FP16InstabilityError    - FP16 numerical instability
└── DeblurError             - Deblurring failed

RETRY LOGIC:
------------
Stream connections use exponential backoff:
- Max retries: 3
- Initial delay: 2 seconds
- Backoff factor: 2x

GRACEFUL DEGRADATION:
---------------------
Components can be disabled after repeated failures:
- Error count tracked per component
- Component disabled after 5 consecutive errors
- Pipeline continues with reduced functionality
